## Plan

**Approach:** Use OpenTelemetry's standard instrumentation packages (`opentelemetry-instrumentation-{fastapi,sqlalchemy,redis,httpx}`) orchestrated through a unified `src/observability/instrumentation.py` helper. Instrument the FastAPI app at ASGI application configuration time in `src/main.py` so server spans wrap all downstream middleware, and instrument database, Redis, and HTTPX client operations globally so they automatically record as child spans under active server or background task spans. Preserve `RequestIdMiddleware` as the sole request access logger while extracting and continuing inbound W3C `traceparent` headers without duplicate logging or real network/Redis I/O under `ENVIRONMENT=test`.

**Files:**
- `pyproject.toml` — modify: Add dependencies for `opentelemetry-instrumentation-fastapi`, `opentelemetry-instrumentation-sqlalchemy`, `opentelemetry-instrumentation-redis`, and `opentelemetry-instrumentation-httpx`.
- `uv.lock` — modify: Lock the added OpenTelemetry instrumentation dependencies via `uv lock`.
- `src/observability/instrumentation.py` — create: Implement `instrument_auto`, `instrument_fastapi`, `instrument_sqlalchemy`, `instrument_redis`, `instrument_httpx`, and `uninstrument_auto`.
- `src/observability/bootstrap.py` — modify: In `reset_observability`, preserve the `_PROXY_TRACER_PROVIDER` singleton instance while resetting its delegate `_provider` to ensure module-level instrumented tracers dynamically bind to newly initialized tracer providers.
- `src/observability/__init__.py` — modify: Re-export the instrumentation helper functions.
- `src/main.py` — modify: Call `instrument_auto(app)` after middleware registration to ensure `OpenTelemetryMiddleware` wraps incoming requests before `RequestIdMiddleware` executes.
- `src/worker.py` — modify: Call `instrument_auto()` in `setup_worker_services()` to instrument SQLAlchemy, Redis, and HTTPX for background worker tasks.
- `tests/test_request_id.py` — modify: Update `test_request_id_generated_when_missing` UUID assertion to accommodate 32-character hex trace IDs produced by server spans.
- `tests/test_auto_instrumentation.py` — create: Add comprehensive test suite verifying server spans, child database and httpx spans, inbound `traceparent` continuation, single access log line, Redis child spans, and zero network/Redis I/O under `ENVIRONMENT=test`.

**Risks / watch-outs:**
- Middleware ordering in FastAPI: `FastAPIInstrumentor.instrument_app(app)` must be invoked after Starlette middlewares (`RequestIdMiddleware`, `CORSMiddleware`) are declared in `src/main.py` so that `OpenTelemetryMiddleware` becomes the outermost ASGI layer and initializes the server span before `RequestIdMiddleware` executes.
- Pre-existing SQLAlchemy engine initialization: `sessionmanager` in `src/config/database.py` creates an engine at module import time; `instrument_sqlalchemy` must instrument both the global hook and any already-instantiated `sessionmanager.engine.sync_engine`.
- Test client correlation interference: In tests using `AsyncClient(transport=ASGITransport(app=app))`, global HTTPX instrumentation would instrument the test client itself if not scoped; verifying server span assertions by filtering on `SpanKind.SERVER` ensures clean isolation.
- Tracer proxy delegation across test resets: Resetting `_PROXY_TRACER_PROVIDER` by replacing the object breaks proxy tracers cached by instrumentors; resetting `_PROXY_TRACER_PROVIDER._provider = None` instead preserves dynamic delegation to the new `TracerProvider`.
