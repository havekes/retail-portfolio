**Risks / watch-outs:**
- The `request: Request` parameter is mandatory for slowapi to apply the limit — a decorator without it silently does nothing. The rate-limit test (429 assertion) is the guard against this.
- Limiter state is module-global with `memory://` storage in tests: `limiter.reset()` in a fixture is required or rate-limit state leaks between the new tests and neighboring suites.
- `user_or_ip_key_func` reads `request.cookies["auth_token"]` or the `authorization` header — dependency-override tests bypass real auth but the key func reads the raw request, so if the rate-limit tests send no token, keying falls back to IP (shared across tests). Either send a real signed cookie/JWT (as `tests/routers/test_rate_limit.py` does) or accept IP-keying and assert the cap on a single key exclusively.
- The 30/minute cap number is an implementation decision the ticket left open — confirm with reviewer or state it in the PR.
- Frontend `reportError` is `void`-ed (best-effort): tests must inject the explicit transport argument into `showToastForApiError`'s report path (existing `reportError(error, context, transport)` overflow) or spy on the module — the ticket's technical note supports this pattern.
