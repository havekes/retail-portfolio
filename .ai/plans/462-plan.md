## Plan

**Approach:** Move all security/price fetching client-side, matching the T01 pattern from `#460`: `+page.server.ts` stops contacting the market service entirely and returns only the cheap route identity (`security_id`), while a new Layer-2 service (`$lib`-colocated class, instantiated per page — Gotcha 3) owns the async data wave (security + prices) behind a single `load()` method that never throws and returns caught errors. The page consumes it via a mount-time browser `$effect` keyed on `data.security_id` (fires once per soft navigation, browser-only since effects don't run in SSR), feeds a caught 401 through the shared `redirectOn401` seam from `frontend/src/lib/api/async-data.ts`, and keeps every other side effect (candle mapping, preferences, alerts/holdings/snapshots, dynamic chart import, saved-timeframe refetch, initial wave-alert reconcile) triggered by data resolution instead of `data.items` presence. Rejected alternative: SvelteKit streamed promises from the server load — rejected because a streamed promise's rejection can't become a client redirect (noted in the ticket), so it would need a second error-marshalling shape on top of the T01 seam; instant titlebar navigation still works because the client can resolve symbol/name from `watchlistService.defaultWatchlistSecurities` before the fetch resolves.

**Risks / watch-outs:**
- Server-side behaviors die with the rewrite: direct visits with an expired session no longer get a server 302 + `deleteAuthCookie`. The T01 seam + `hooks.server.ts` `clear_session` handling must cover it — confirm during implementation that the 401 test exercises the seam path, not the old server path.
- The initial wave-alert reconcile must stay gated on preferences (`userPreferences !== null`) — a failed `getPreferences()` called from the service-driven init chain could otherwise mass-delete wave alerts.
- Soft navigation re-entry: the mount `$effect` must be keyed on `data.security_id` (re-fires per security and resets the drawing tool state) — if keyed on resolved data it can double-run when the price wave overlaps a second navigation; also avoid clobbering a newer in-flight load (the old `data.items` effect had no such risk).
- `setChartDrawingsService`/`ChartDrawingsService` init reads `security?.id` via `untrack` at component init — with initially-null service security it must tolerate the id arriving later (the existing `setSecurity` `$effect` handles this; verify).
- Instant titlebar depends on `watchlistService.defaultWatchlistSecurities` being populated — direct URL loads may show the skeleton instead until the fetch resolves; that's acceptable per the ticket ("real symbol/name, **or** title skeleton while unresolved").
- The watchlist page (`#465`, T02) and layout already touch `watchlistService` mega-state — re-running the security fetch should not mutate watchlist state the layout's shortcuts read.
