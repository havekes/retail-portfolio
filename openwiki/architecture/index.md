- [Authentication & Authorization](authentication.md) - The cross-stack identity system — signup and email verification, password/TOTP/passkey login, HS256 access and mfa_pending JWTs, the httponly auth_token cookie, the SvelteKit SSR guard that re-verifies the same secret with jose, Redis-backed challenge/lockout/denylist state, the signed WebSocket ticket, 404-not-403 ownership authorization, and the separate shared-secret X-Service-Token boundary that guards the market data plane.
- [Chart Drawings, Plugins & Rewind](chart-drawings-and-rewind.md) - The chart drawing system end to end — the per-plugin series-primitive contract and helper stack, the finance-math boundary, ChartDrawingsService as the single owner of drawing state, preference persistence, undo/redo and snapshot saving, the live-versus-snapshot-scoped effective views, and the snapshot-to-rewind pipeline from Postgres to the security page.
- [Charting: Chart Surface, Panes & Indicators](charting.md) - The chart rendering surface of the security route: security-chart.svelte's mount/series/primitive lifecycle, candle updates, pagination and future whitespace, the scaleMargins price-scale pane model with custom pane heights, price-scale zoom/auto-scale interaction, timeframe and chart-style preferences, the two indicator paths (in-process Python on market_router versus POST .../indicators/compute dispatching specs to the Go sidecar with a Redis result cache) and their out-of-order guard, chart settings, the price-alert primitive and the rewind-aware valuation band.
- [Configuration, Dependency Injection & Cross-Cutting Runtime](configuration.md) - How retail-portfolio loads settings from the single root .env, enforces the SECRET_KEY / MARKET_DATA_SERVICE_TOKEN / FMP + POLYGON startup rules, resolves the endpoint-cache TTLs at call time, selects stub or live integrations, wires the svcs registry for both the API and the Huey worker across the legacy EODHD and the new composite data-plane gateway bindings, and provides database, Redis, rate limiting, request-ID, logging and email infrastructure.
- [Backend Domains, Layers & Route Map](domains.md) - Catalog of the backend domains (account, auth, market, integration, ws, core, config) with each one's models, public APIs, services and routes, the router → api → service → repository → model layer rules and their invariants, and the two serving surfaces of the market domain — the user-JWT `market_router` and the service-token `data_router` that resolves the provider-agnostic `DataPlaneMarketGateway`.
- [Frontend Architecture (SvelteKit)](frontend.md) - SvelteKit 2 / Svelte 5 SSR application structure — the route map and what each load awaits, the post-navigation data-wave pattern with page-owned rune services and redirectOn401, the ApiClient layer over the user-JWT /api/v1 surface (including the market client's institutional-ownership helper) with SSR token override, context-provided state classes, the layout/sidebar/global-search composition, the security route's actions sidebar, and the SSR pitfalls the codebase enforces.
- [Market Data Plane: Providers, Caching & the Service Endpoint Contract](market-data-plane.md) - The backend's provider-agnostic service-to-service market data plane — the eight /api/v1/market/data routes and their frozen OpenAPI contract, the DataPlaneMarketGateway key over the FMP/Polygon composite, EndpointResponseCache layering with negative caching, listing-currency and price-aggregation semantics, and provider-agnostic error mapping.
- [Architecture Overview](overview.md) - System-level runtime map of retail-portfolio — the FastAPI backend (lifespan migrations, eager data-plane gateway probe, svcs registry, middleware order, error handling), the Huey worker, the SvelteKit SSR frontend, the two Go services (the stateless indicator calculator and the MCP gateway that talks only to the backend data plane), PostgreSQL/Redis/mailcrab, the user-JWT versus X-Service-Token request paths, route mounting under /api/v1, health probes, the backend layer rules, and the commands that verify a change.
